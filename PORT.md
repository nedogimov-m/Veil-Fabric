# Veil 26.3 port

Status: **native GPU, resource and postprocessing components work on 26.3 Vulkan; the complete mod still does not compile or launch**.
No partial Veil mod JAR is published or substituted for the complete library.

## Origin and license

- Repository: https://github.com/FoundryMC/Veil

## Implemented migration

- Standalone Fabric Loom 1.18.4, Gradle 9.7.0 wrapper with SHA256, Minecraft 26.3, Java 25, Loader 0.19.5 and Fabric API 0.163.0+26.3.
- Replaced `ResourceLocation` with the actual 26.3 `Identifier`; moved `net.minecraft.Util` to `net.minecraft.util.Util`.
- Migrated access-widener namespace to `official`, which unobfuscated 26.3 requires. **Its legacy rendering entries still need a target-by-target audit before any runtime claim.**
- Real networking providers use `clientboundPlay`/`serverboundPlay`, Netty `ChannelFutureListener`, current server access and `ChunkPos.containing`. Tracking uses Fabric `PlayerLookup`; direct sends no longer depend on unsafe `PacketSink` casts.
- Registry providers use `ResourceKey.identifier`, `Registry.getValue`, `getOrThrow` and `FabricRegistryBuilder.create`.
- Resource codec loading retains invalid-file isolation, registry-aware decoding and duplicate checks. Its logger no longer initializes the entire Veil renderer/platform graph merely to load server resources.
- PoseStack mixin uses 26.3 `rotate(Quaternionfc)`, `rotateAround(Quaternionfc, ...)`, `poses`/`lastIndex` and `last()`. Reused PoseStack storage must be addressed by the active index rather than list length.
- All live rendering and optional-integration sources remain in the default build. There are no replacement no-op renderers, disabled source groups or fake compatibility classes. The unreferenced GL ShaderTextureCache implementation was retired only after its real native texture/sampler cache, ownership and consumers migrated, with its original source preserved under `upstream-retired`.
- Real RenderPearl GPU framebuffers implement multiple color attachments, depth, clear/copy, resize, transactional allocation, and owned/borrowed texture/view lifetimes. Native fullscreen passes perform scaled color sampling with a compiled pipeline and actual sampler.
- Native shader programs own compiled immutable pipelines and typed std140 UBOs. ShaderManager loads real JSON definitions, caches draw-state variants, applies blend equations/predefinitions/includes, resolves fresh texture views, and releases variants when their draw owner retires. TextureFilter creates actual native samplers; unsupported legacy extension algorithms fail explicitly.
- The eight world callbacks bridge actual Fabric `LevelRenderEvents`, in native order: `COLLECT_SUBMITS`, `START_MAIN`, opaque terrain, solid features, translucent features, before/after translucent terrain, `END_MAIN`. Geometry is submitted through the real node collector. Extra explicit GPU passes are restricted to `END_MAIN`, after vanilla closes its render passes.
- Native JSON postprocessing includes Blit/Copy/Mask/Depth stages, typed uniform values, temporary framebuffer scopes, transactional resize, main-target resolution, reload and resource disposal. Migrated post shaders explicitly declare their std140 block; `PostUniforms` begins with `vec2 InSize`, `vec2 OutSize`, then configured fields sorted by name. The post renderer no longer sets global GL state.
- Fourteen property classes now write native typed uniform blocks and texture/sampler bindings. Their Flare model/material consumer graph still requires migration.
- Serialized fixed-size, resizable and borrowed ShaderBlock implementations now use genuine native buffer slices, explicit uploads and named bindings. LayoutSerializer computes std140 offsets without GL reflection, including correct column padding for square and rectangular matrices; VeilShaderBufferLayout defaults to std140 and can declare a stable block name. The registered cache and native compile-event types are migrated. FlareMaterial now declares/prepares its property block (including inverse matrices); its model draw consumer remains to port.
- ShaderUniform/ShaderUniformImpl now expose borrowed typed views into named native UBO fields, with pending CPU reads and explicit later upload. Scalar/vector/array and square/rectangular matrix operations use std140 offsets/strides. Integer texture handles are rejected in favor of native texture views/samplers. Numeric double/long setters convert into the declared 32-bit field with range checks; this does not advertise unsupported 64-bit shader execution.
- ShaderProgram, UniformAccess, TextureUniformAccess and the resource ShaderProgramImpl now use explicit native pass/buffer/texture contracts. Native shader metadata comes from declared layouts and actual buffer ranges; external schemas remain explicitly unknown. Per-draw CPU snapshots use immutable bytes, distinct aligned native transient UBO ranges, captured external references and texture maps so queued draws retain their own values. Resource-defined programs retain their JSON definition and macro provenance.
- Queued draw leases now retain native program resources and replaced owned samplers across manager retirement; actual disposal follows the final submitted draw lease. Hot-recompile work retains last working variants until all replacements compile, and native compiler-observed include IDs drive resource edits without GL shader reflection.
- Serialized ShaderBlock selections now capture immutable CPU bytes for each deferred draw. Later Java-object mutation, resize, unbind and disposal cannot overwrite queued values; borrowed slices retain explicit caller ownership. Native program JSON can declare external buffers with `"uniform_blocks":["BlockName"]`.
- The native render-type boundary compiles 37 production classes plus two acceptance entrypoints and passes actual Vulkan layer replay, resource codecs/cache and generic state modifications. Production code binds the managers and selected blocks, flushes at `END_MAIN`, and releases pending owners before shutdown. Full lifecycle execution remains blocked by the surrounding unported renderer. See [the detailed render-type evidence](RENDERTYPE_PORT.md).
- Reusable meshes now own actual native vertex/index buffers, consume Minecraft MeshData, preserve sequential/sorted indices and named instanced formats, and execute direct/instanced/indirect commands in an explicit pass. Draw leases retain replaced buffers through submission; borrowed ranges preserve external ownership. See [the native mesh contract and evidence](MESH_PORT.md).
- Real GLSL AST preprocessor registration now feeds the native ShaderManager. Root/include contexts, native/custom imports, processor-discovered macro/include dependencies and failed-processing preservation operate on actual native shader pixels. The production renderer forwards its registration event. NativePipelineBridge also intercepts genuine eager/lazy vanilla pipeline compilation and binds explicit extension resources inside the actual frontend pass. See [native world shader ownership](WORLD_SHADER_PORT.md).
- Genuine Inspector/SingleWindowInspector contracts use current Component/Identifier types and explicit editor visibility ownership. Their CPU behavior compiles/runs without starting the global renderer or installing the old ImGuiMC backend; a compatible UI render backend remains required.
- ShaderInspector now browses actual live native pipelines without compiling debug selections. Weak cache observations cover both native get/insert paths, plus direct Veil pipelines. It displays immutable state/layouts, typed CPU UBO values, textures/samplers and dependency provenance, reads/copies real source resources and edits definitions. Unknown external schemas remain explicit. Native modded cache entries are visible; direct backend-specific Iris/Sodium introspection and actual ImGui window rendering remain pending.
- Native dynamic MRT targets retain immutable mask/size generations, preserve caller-owned pass descriptors and append actual typed attachments/pipeline color states. The real AST processor emits native lightmap/albedo data, explicit matched varyings and geometric normals for the 26.3 block format without normal attributes. Independent native variants detach source before asynchronous work; their native cache/leases retain queued owners and release abandoned pending compilations on the render executor. Automatic world-pass selection, translucent/OIT composition, managed shader consumers and the old dynamic manager remain to migrate. See [the dynamic MRT boundary](DYNAMIC_BUFFER_PORT.md).

## Reproducing dependency preparation

From the suite root:

```sh
python3 ports/veil/scripts/fetch-libraries.py
export JAVA_HOME=/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home
./gradlew -p ports/veil compileJava --console=plain
```

The final command currently fails for the renderer API migration described below. The sibling Create wrapper can also run the same standalone project with `-p ports/veil`.

The fetch script checks exact cryptographic hashes before using any artifact. It extracts the genuine platform-independent Molang 3.1.1.19 and GLSL Processor 0.2.3 libraries from the originally published Veil 4.3.2 Fabric JAR. This avoids intermittent Java TLS failures against the upstream Maven host. The original Maven POMs are retained under `local-maven`; no synthetic library implementations or POMs are used. All downloaded binary files are ignored and reproducible with the script.

The old Veil JAR is only an extraction source. ImGuiMC 1.1.0 and Sodium 0.8.12-alpha.2 artifacts are compile-only descriptions of the optional upstream integration APIs. They are never packaged or installed as 26.3 runtime mods. Other optional integrations retain their exact upstream compile-only coordinates. They still require 26.3 adaptation.
